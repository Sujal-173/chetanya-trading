# Search visibility and trust checklist

## Already implemented in this project

- Unique title and description for the main routes and insight articles.
- Canonical URLs and shared metadata base.
- Open Graph and Twitter summary-large-image metadata.
- Generated 1200 × 630 social sharing image.
- XML sitemap and robots.txt; API route excluded from crawling.
- Organization and WebSite JSON-LD.
- FAQPage JSON-LD with visible matching FAQs.
- Article JSON-LD for insight posts.
- Semantic headings, page landmarks, image alt text, accessible form labels and responsive image sizes.
- Public `llms.txt` with a concise, accurate site description and key disclaimers.
- Local area information held in environment-backed site configuration, not repeated as invented street-address data.
- Risk and regulatory disclaimers to avoid return guarantees and unsupported registration claims.

## Owner must supply and verify

- Production domain and canonical URL.
- Exact registered business name if different from the brand name.
- Business phone, inbox, WhatsApp and official social URLs.
- Actual operating location or service area and eligibility for a Google Business Profile.
- Real service scope, pricing approach and regulatory status.
- Any registration details, only after checking official records.
- Real founder/consultant biography, qualifications, permitted designations and photographs.
- Actual testimonials only with permission and substantiation.

## After deployment

- Verify domain ownership in Google Search Console.
- Submit sitemap and request indexing for important pages.
- Create or update Google Business Profile using consistent business data.
- Check rich-result/schema output and fix any errors.
- Run Lighthouse and mobile usability checks.
- Add analytics only after choosing a provider and updating the privacy notice.
- Review the insight articles periodically so outdated market context is corrected or removed.
